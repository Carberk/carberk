## Transaction and effect map

All mutating ledger methods now open an interactive transaction. Unlocked selection discovers bounded due roots, full stored rows, absent cleanup/upload/claim-target slots, recursive registry FK endpoints and legacy directory references. The graph includes User, Business, Listing, draft and retained video endpoints where actually reached. Both reverse unique keys, `users.avatarUploadId` and `listing_media.uploadId`, are derived even without adopters. Legacy `key`, `posterKey` and `avatarKey` rows and their parents enter discovery before managed locks. Reference reads return at most 1001 rows and the 1000-slot closure rejects overflow before preparation. They do not truncate an accepted graph.

The ordinary campaign receipt covers actual NEW mutations and every observed dependency before any managed advisory/row/FK/index lock. The existing pure `diagnostic_source_lock_keys_before_intake` derives OLD, NEW and absent keys; no new source operation is invented. Keys are deduplicated and acquired in namespace/key order, with rows locked in that namespace. Full fresh post-wait discovery must equal the initial graph. A changed selector, target, manifest, reference or retry state aborts the transaction rather than extending scope or completing unrelated work. No ordinary receipt is nested in a source-owned transaction.

Batch methods use nonblocking advisory acquisition and `FOR UPDATE SKIP LOCKED`. A contended dependency skips this prepared batch without writes; it does not seek replacement roots after locking. This conservative contention behavior can return fewer roots than the original single-statement scan. It preserves bounds, order and no-duplicate safety; parent inspection must assess this explicit throughput tradeoff. Completion/failure use the same ordered prefix with blocking locks. Existing Prisma transaction timing defaults remain.
