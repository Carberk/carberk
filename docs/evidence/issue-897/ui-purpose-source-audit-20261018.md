## Confirmed findings

### 1. P2: History child forms remain disabled after rejected browser RPC

Locations: `apps/admin/src/app/(admin)/services/HistoryWorkspace.tsx:47` and `:56`; `apps/admin/src/app/(admin)/services/HistoryReportsWorkspace.tsx:17`.

`readPayments` and history `command` set `busy=true`, then await imported Server Actions without catch/finally. The report-artifact `command` does the same. If the browser-to-Next Server Action promise rejects, execution never reaches `setBusy(false)` or `setError(true)`. Child buttons, including Refresh, are disabled through their shared `button` helper, and guards reject subsequent commands. A surrounding parent handler cannot catch these callbacks because children call their Server Actions independently. Reconnecting alone therefore leaves payment, quote/refund or artifact verification/delivery actions unusable until remount. Their read/refresh functions also lack a transport rejection catch.

This is a remaining child path on the current candidate, not a re-report of the repaired `ServiceWorkspace` parent or Diagnostic/Operations handlers. `actions.ts:28-32` wraps API work inside the server process, which cannot catch a browser RPC rejection before its result reaches the client. The existing `ServiceWorkspace.transport.spec.tsx:13-15` describes failed upstream HTTP through real actions, not these browser RPC promises.

Exact approved criterion: `docs/prd/ui/service-workspace.md:31`, "Expose accessible loading/empty/error/retry and uncertain-payment states". Also line 15, "Report upload/download failure has explicit retry/escalation". Affected commands need client-side catch/finally with same-epoch handling and a retryable visible error. No runtime reproduction was run in this audit.

### 2. P2: Delivered customer report cards omit required filename and byte size

Location: `apps/mobile/src/services/HistoryReports.tsx:22-24`.

The entire delivered card renders provider/VIN, original date, optional vehicle/mileage/source facts and document/link actions. It does not render a filename or size. `report.sizeBytes` is used only as the `getBytes` download cap. `packages/contracts/src/schemas/serviceMessaging.ts:81` exposes sizeBytes but no filename, so the filename omission also reaches the response contract. Customers cannot inspect the required file identity/size before opening/downloading; the generic Open PDF label does not supply it.

Exact approved criterion: `docs/prd/ui/service-workspace.md:15`, "Delivered artifact card names provider, confirmed VIN, original date, filename/size and Open PDF/Download plus separately named shared link." At minimum display the available localized size, and supply the actual safe document name through the owned artifact projection rather than inventing one in this audit. No document download was attempted.
