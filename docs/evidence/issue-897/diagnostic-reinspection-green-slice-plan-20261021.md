## Finding

The existing source settles the mechanics of a new observation, but it does not settle the full reinspection policy.

- D2 is **not settled for manual or changed identity**. The order stores either a VIN or a free-form `manualReference` ([diagnostics.ts](../../../packages/contracts/src/schemas/diagnostics.ts#L23-L29)); public observation checks a normalized VIN against the current Listing and then stores only `listingIdentityDigest` ([PrismaDiagnosticIntake.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticIntake.ts#L204-L219)). There is no durable cross-order identity or approved rule for comparing manual references, changed VINs, or a changed vehicle. The safe source slice therefore accepts only the already-proven path: both observations use method `vin`, both VINs normalize equal, and the current Listing digest still validates. Manual or changed identity must fail with the existing reinspection rule error until D2 is decided. The route and test must describe this as a bounded identity case, not as the general reinspection policy.
- D3 is **not settled for public commissioner transfer**. Intake records the commissioner on each order, while public observation and release authorize the Listing and its current identity ([PrismaDiagnosticIntake.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticIntake.ts#L51-L79), [PrismaDiagnosticReports.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticReports.ts#L176-L191)). Feature 50 excludes private-to-public conversion and cross-buyer reuse ([feature 50](../../../docs/prd/features/50-reports-tier.md#L31-L35)); flow 66 excludes reusing another commissioner's snapshot ([flow 66](../../../docs/prd/flows/66-diagnostic-inspection.md#L69-L69)). Nothing chooses whether a later public order by a different commissioner may succeed. The safe slice must require equal non-null commissioners for both audiences, including public, while retaining the same-Listing check. That preserves the hosted positive and leaves transfer policy explicit for a later decision. Do not infer that a current Listing publisher may transfer report authority.
- D5 is **sufficiently safe for this slice, but not a new policy decision**. `dto` already projects `supersededBy` by released successor id only, and access is scoped through the report's own order ([PrismaDiagnosticReports.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticReports.ts#L48-L57), [DiagnosticReportAccess.ts](../../../apps/api/src/modules/diagnostics/infrastructure/DiagnosticReportAccess.ts#L14-L19)). A draft successor therefore does not expose an id, and a released successor id is visible only to a reader already authorized for the predecessor. Keep `successorOf` in the new report and existing `supersededBy` in the old report. Do not add predecessor-order joins, cross-order staff browsing, or a new global lineage endpoint. Whether predecessor-order staff should see a draft successor remains an acceptance gap, not a reason to widen this slice.

The contract and HTTP evidence support this boundary. ADR-0104 requires immutable audience-preserving history and reinspection/history acceptance ([ADR-0104](../../../docs/adr/0104-center-diagnostics-with-private-and-public-reports.md#L20-L40)); feature 50 requires a new date/mileage snapshot and preserved old snapshot ([feature 50](../../../docs/prd/features/50-reports-tier.md#L106-L106)); flow 66 requires a new physical observation and says a reinspection is not an editorial correction ([flow 66](../../../docs/prd/flows/66-diagnostic-inspection.md#L41-L42)). The hosted RED is route absence at `DiagnosticReports.e2e.spec.ts:308`, run `39534489428`, API `119007918038`, published commit `46f9ab8a`; the log records expected 201, got 404 ([plain log](/tmp/carberk-next-release-20261021/46f9ab8a-api.plain.log:2478)).

## Safe implementation boundary

Implement the proposed route `POST /api/v1/diagnostics/orders/:id/reinspections` with the proposed strict body and no change to `DiagnosticReport.reinspect`. Use the selected D1 authority: the currently assigned technician links the predecessor while creating the new draft. Do not add a commissioner-declared predecessor field or grant the technician predecessor read access. The domain already enforces finalized/withdrawn predecessor, a different order, non-decreasing observation date, new mileage, empty findings, new template, and preserved predecessor state ([DiagnosticReport.ts](../../../apps/api/src/modules/diagnostics/domain/DiagnosticReport.ts#L113-L122); its focused spec covers the new-order and old-measurement invariants ([DiagnosticReport.spec.ts](../../../apps/api/src/modules/diagnostics/domain/DiagnosticReport.spec.ts#L65-L75))).

The infrastructure operation should:

1. Authorize the current technician assigned to the new order, then check the new order's version, arrived state, physical authorization, observation, and empty first-report state. Do not grant predecessor access. Keep authority checks ahead of conflict checks so unauthorized callers receive 403.
2. Load the predecessor by id and require it to be finalized or withdrawn, not erased, audience-equal, snapshot-backed, successor-free, and on a different order. Require equal commissioners and, for this first slice, equal normalized VIN observations plus the new order's current public association when audience is public. A mismatch maps to the existing uniform 403; an unsupported manual/changed identity maps to `REPORT_REINSPECTION_REQUIRED` until D2 is resolved.
3. Insert the report with the new order's pinned template and observation, `successorOf=predecessorId`, reason, and empty findings. Preserve the existing correction path. The new boolean `reinspection` is a discriminator only; it must never be inferred from `predecessorId`, and it must be included in the immutable identity trigger.
4. Enforce one first report per order with the proposed partial unique index (`predecessorId IS NULL OR reinspection`). Keep the predecessor unique constraint so correction/reinspection races resolve as a conflict. The INSERT trigger must validate cross-order audience, commissioner, identity and snapshot conditions. It must not apply those cross-order checks to ordinary UPDATEs.
5. Stop the evidence walk at a reinspection row. A later correction may use evidence owned by that reinspection report only. The current walk rejects a predecessor from another order ([PrismaDiagnosticReports.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticReports.ts#L96-L110)); changing it to cross order without the stop would leak private evidence and would invalidate the hosted negative assertion.
6. Make idempotency explicit. A repeated `reportId` with the same order, predecessor, reason and author returns the existing draft without a second audit. Any differing tuple is a conflict. Concurrent correction and reinspection attempts must converge through the predecessor unique constraint and map to `DIAGNOSTIC_REINSPECTION_CONFLICT` or the existing correction conflict.
7. Use one transaction and a stable lock order: lock the public Listing first when present, then both order rows in ascending id order, then predecessor and successor report rows in ascending id order, then insert and audit. Do not call the existing single-order authority lock and later acquire the other order in an order-dependent sequence. This avoids a correction/reinspection deadlock while preserving Listing identity serialization.
8. Keep snapshots and artifacts immutable. Finalization creates the new report snapshot and three new PDF artifact rows. Withdrawal removes current public availability with no fallback. The existing public selector already chooses the newest released report and never falls back ([PrismaDiagnosticPublic.ts](../../../apps/api/src/modules/diagnostics/infrastructure/PrismaDiagnosticPublic.ts#L17-L25)). Account erasure must remain survivable: erasure may null commissioner/listing on the order, but must not cause an UPDATE-time reinspection identity guard to reject fencing ([diagnosticAccountErasure.ts](../../../apps/worker/src/jobs/diagnosticAccountErasure.ts#L42-L50)).
