# Owned Listing video protocol V1

Decision contract for #889 under #886/#897, ADR-0099 and existing ADR-0079/0088/0089. This defines implementation for #890–#896. The accompanying executable proof is isolated from the app. There are no production endpoints, shared contracts, migrations or enabled audiences in this checkpoint.

## Ownership and closed defaults

Listings owns the optional video association. Identity owns account status and the server-authorized actor; operations owns tester grants and rollout state. Require authenticated, active owner plus explicit uploader eligibility for every create/resume/renew/complete/adopt/reprocess operation. Viewing/poster eligibility is also tester-only, independently checked; uploader membership does not silently grant public viewing. These capabilities default closed. The stop-new-uploads switch does not revoke otherwise authorized existing playback. A separate viewing/revocation switch can stop new reads. Never infer rights from a User-supplied account id, object path or mobile flag.

Use separate video ports for multipart storage, codec validation, processing and authorized read streaming. Leave existing photo endpoints, `MediaStoragePort`, image caps and `conditional-v1` image cleanup untouched. No external media service or paid activation is selected.

## Upload session contract

Additive namespace `/api/v1/listing-video-upload-sessions`. Every request is authenticated and checks owner, intended target and current capabilities. Generic unavailable responses cover unknown/foreign/expired/cancelled sessions without revealing their existence. Session creation accepts only an owned draft or owned editable Listing, a client idempotency key, prepared file size/hash and an integer poster offset relative to the prepared selected interval. No original phone path, raw asset provider id, client object key or arbitrary upload id is accepted.

| Operation | Request / authoritative response |
|---|---|
| POST collection | `{protocolVersion:1,target:{kind:"draft"|"listing",id},prepared:{sizeBytes,sha256},posterMs,idempotencyKey}`. Response `{version:1,sessionId,generation,state,expiresAt,partBytes:5242880,partCount}`. Same actor/key/identical input returns same session; changed input conflicts. |
| GET `/:sessionId` | Current durable state plus storage-confirmed `{partNumber,sizeBytes,etag}` list, expected total/part bytes and expiry. ListParts is paginated and reconciled server-side. ETag is an opaque protocol token, never a content hash. |
| POST `/:sessionId/part-credentials` | Requested part numbers only, bounded to expected range. Response presigned UploadPart URLs, required headers and credential expiry. Signed owner/bucket/key/UploadId/part/length are generated server-side. Initially one active part; credentials expire after at most15min and never beyond session expiry. No storage key/credential enters diagnostic payloads. |
| POST `/:sessionId/pause` | Persist PAUSED intent before mobile cancels its native PUT. ListParts may later confirm the just-finished part. Resume clears intent after current owner/target eligibility is rechecked. |
| POST `/:sessionId/complete` | No trusted client-completed-part list. Server lists all parts, checks exact consecutive sequence/sizes/total, uses authoritative ETags, fences completion and returns PROCESSING after proven object commit. Replay returns the same committed generation. Never returns READY merely from HTTP200 or multipart completion. |
| DELETE `/:sessionId` | Persist cancellation fence and durable cleanup work immediately, return202 CLEANUP_PENDING until absence is verified. Idempotent; foreign/adopted session cannot delete public media. Public video removal uses Listing lifecycle instead. |

All JSON errors have stable codes and localized clients own copy. Exact names are new additive V1 shared contracts to commit with #890, not mutations to current presign responses. Apply existing transport auth/rate/body limits and a bounded request idempotency record. Hash and limits are declarations until actual content validation; do not treat them as trusted evidence.

Use 5MiB parts except final. For bytes N, expected part count is ceil(N/5242880), every preceding part exactly5242880 and final exactly N minus previous bytes. Credentials renew independently of confirmed progress; recovery never resends a confirmed part just because an API token expired. Native copying creates one bounded temporary part file and legacy Expo native PUT uploads that file. Do not base64 a recording or buffer it fully in JS/API. Source preparation remains #888/#893. Session expiry is immutable createdAt+7days, exact deadline refuses renew/complete. Duplicate signals/retries never extend it. The seven-day scanner applies to abandoned uploads, not an attached usable source.

## Durable state and races

Proposed additive records, to be migrated by the designated schema writer in #890/#891:

- `VideoUploadSession`: immutable owner/target/generation/bucket/key/storageUploadId/expected bytes/hash/version/expiry; state, pause/cancel/completion fence and idempotency binding. Unique server-generated session and source key. Index expiry/state and owner/target lookup. Store no presigned URL.
- `ListingVideoGeneration`: stable video/media identity plus unique generation, source upload provenance, measured source facts/hash, poster offset, processing version/state/error classification, exact asset manifest and retirement state. No user-selected poster key.
- Listing association or equivalent transaction-owned record with one active ready generation and at most one pending replacement. Compare-and-swap revision fences remove/replace/process races. New columns/relations are nullable/additive for old clients.
- Durable process/cleanup work and playback grants with appropriate expiry/state indexes. Hash grant secrets; bind owner, Listing, generation, purpose, allowlisted assets and expiry. Never store/log a usable bearer URL.

Session states are UPLOADING, PAUSED, COMPLETING, PROCESSING, FAILED, CANCELLED/CLEANUP_PENDING and DELETED; READY/ADOPTED belongs to validated generation/adoption. PostgreSQL row locks/CAS own state transitions, not per-process memory or BullMQ job dedupe. DB transactions must not hold locks across object transfer/transcoding. Persist a completion fence/outbox first; execute storage outside the transaction; reacquire and verify the same fence before committing the processing association. The source key is unique and fixed, so a lost complete response can reconcile HEAD plus authoritative session provenance without replaying a missing multipart upload. A worker then verifies full hash/content. A matching length or client metadata alone does not prove ownership or decode validity.

Cancellation always wins over a still-unadopted late completion. Persist the fence first; refuse new credentials/complete/adopt; abort multipart, then verify parts are absent, and delete any completed unadopted unique source/object manifest. AWS permits in-flight parts to finish after abort. Repeat abort/list/absence verification with durable backoff until drained; a single Abort success cannot mark DELETED. A concurrent in-flight completion keeps cleanup pending, and its reconciliation must retire/delete rather than adopt. Uncertain storage errors keep pending work. A seven-day expiry/restart sweeper reconciles stranded COMPLETING and pending cleanup with bounded pages, no orphan-prefix deletion. No adopted or live-generation object may be deleted.

## Readiness, posters and replacement

Worker probes actual uploaded bytes under bounded input/time/memory/temp-space limits. Validate MP4/H264/AAC-or-silent, measured duration>0 and<=90000ms, size, supported dimensions/frame cadence/colour and full decode. Reject invalid content even if phone metadata passed. 10min/2GiB source and15MiB prepared cap remain provisional #888/#896 resource policy, not proof from this contract.

`posterMs` is an integer in `[0, measuredDurationMs)`, relative to the prepared clip, whose actual origin is zero. Recheck after server probe; invalid timestamps fail recoverably, never clamp to an unrelated frame or trust a client image. Server decodes that timestamp and generates authoritative poster sizes using current photo-tile geometry. Missing/undecodable frame fails processing before readiness.

Self-hosted FFmpeg worker initially converts one job at a time. A generation owns an exact manifest of source, poster files, master/media playlists, init fragments if any and every segment. Every reference must resolve within that manifest; no external URI, traversal, symlink/key escape or user-supplied key is accepted. V1 output uses plain relative safe asset paths. Produce actual available240/360/720 tiers without upscaling, preserving full-frame orientation/aspect/audio. HLS no-content encryption is selected for V1; any later key URI needs the same grant rewrite/authorization.

Persist READY only after source validation, authoritative poster validation and every required exact manifest object exists/readback is usable. Hash/version facts belong to the worker result. Queue completion, a DB flag, one accessible master or successful client PUT is insufficient. A generation can transition public only if it still matches the current pending fence and Listing has not removed it. Replace by atomically switching active generation after readiness; old ready video stays public while a replacement uploads/processes/fails. Removal immediately clears active/pending associations and revokes grants, then retires the complete owned manifest with durable retry. Out-of-order jobs may finish private cleanup work but can never revive an old association. Draft publication with required photos does not wait for optional pending video; reconcile target binding atomically at publication.

Keep existing exclusive adoption and retirement transaction protocol. A Media Upload belongs to the initiating User and can back at most one authorized target. New video upload state must participate in that common fence, including Listing publish/attach/removal, moderator removal and account purge. Extend cleanup with a separate video manifest handler; the image cleanup's strict pending UUID namespace and five/historical-nine object manifests must not be widened to arbitrary video directories. Retain attached compressed source for operator reprocessing, never raw original phone recordings. Reprocessing emits a fresh generation/fence and cannot mutate active assets in place.

## Serving and cache authorization

Use explicit private owned video asset bucket/keys, not extension-based `inferBucket`. Existing adapter sends any non-mp4/mov key to photo storage, so `.m3u8`, `.ts`, `.m4s` and posters need the new explicit video storage/read port. Source files have no public route. Storage policy denies anonymous GET; no public/CDN URL or redirect bypasses the gateway.

After eligible poster read or explicit Play, mint a cryptographically random opaque capability, store only its hash and return same-origin HTTPS `/video-grants/<secret>/<assetPath>`. Bind to grant owner/current account status, Listing, immutable generation, purpose, finite asset membership and short expiry. Default playback TTL5min; poster read TTL60s. They are renewable via authenticated owner/viewer eligibility check, never beyond any actor session/revocation policy. Grant refresh preserves intended playhead/mute/pause, belongs to #895 and never automatically restarts after a denied request. Sign-out/release revokes the relevant grants. Current allowlist/account/Listing/generation checks run on EVERY manifest, media playlist, segment, range and poster request, including previously minted grants. A copied bearer capability can be shared until revoked/expired; this is not device-bound DRM.

Rewrite ALL manifest child URIs, including variant playlists, segment and init-map attributes, into that grant namespace. Relative URLs retain the capability prefix. Never rely on nested iOS custom Authorization header inheritance. Worker validates manifest references against the generation's exact inventory; gateway repeats path/membership checks and rejects external, protocol-relative, encoded/traversing or unknown references. Purpose-scoped poster grants cannot fetch streams and vice versa. Moderator/report inspection requires its own explicit actor/purpose eligibility; a support report is not a public audience grant.

Every response, including errors, uses `Cache-Control: private, no-store`; no shared CDN cache or persistent Expo player caching. Gateway streams with backpressure, bounded concurrent connections/ranges/timeouts and no whole-object API buffering. HEAD/GET/range responses all reauthorize; no redirect exposes private storage. Scrub capability paths/queries from access logs, traces, crashes, referrers and analytics before enabling routes. New requests after ban/deletion/allowlist removal or active-generation replacement fail uniformly; sold/removed-from-sale visibility follows existing authorized photo access rules, not an invented active-only video policy. Bytes already fetched/decoded cannot be recalled. Abort existing streams on observed revocation where feasible, but do not describe that as recall.

Native feasibility proof uses actual desktop AVFoundation fetching an HLS master, variant and segment through the protected namespace and decoding a pixel buffer. No custom headers were needed. This tests the chosen URL mechanism, not Expo SDK55 iOS/Android integration, UI controls, range/seek/quality changes, expiry renewal, HTTPS deployment or network startup targets. Expo-video native source already establishes URL-source support; exact runtime coverage remains #895/final campaign, including Android environment restoration. No simulator boot ran for #889.

## Delivery and activation order

1. #890 adds nullable V1 schema/contracts, authenticated session service, explicit bucket adapter, expiry/cleanup records and hosted actual storage/API race tests. Coordinate schema ownership with #900; this proof changes none.
2. #891 deploys the matching worker processing/cleanup version with FFmpeg/ffprobe binaries pinned in the owned image, bounded resources/concurrency/retries and durable outbox reconciliation. The present video-transcode processor permanently rejects jobs, so never enqueue new production protocol work before this consumer is ready. During rollout, incompatible workers reject a version rather than treating it as legacy work.
3. #892 exposes authorized ready descriptors/posters/Play grants; old clients still receive compatible photo arrays and cannot attach a video key through legacy photo paths. Optional additive video identity/readiness/rendition fields must not force old clients to parse a new photo subtype. Legacy presign10MB video metadata is not the new protocol and cannot bypass tester/ready fences.
4. #893/#894 complete source picker/native preparation and resumable part transfer/recovery. Preserve #888 remaining Android/HDR/provider/resource gates. #895 integrates SDK55-aligned expo-video and final native controls/intentional playback.
5. #896 proves storage/provider/versioning, worker capacity/egress/cleanup and audience gates, then activates only explicitly authorized testers. Default closed until all applicable runtime evidence passes. No paid resources, wider rollout, production promotion or store release is authorized by this proof.
