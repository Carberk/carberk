# First-party measurement boundary

This module owns validated measurement intake and the public post-commit emitter port. Source contexts own their facts. It is separate from Listing-view counters, diagnostics SDK intake and durable market knowledge.

[AcceptMeasurement](application/AcceptMeasurement.ts) applies the shared dictionary and server-owned purpose/population/origin policy. [The public ports](measurement.public.ts) require atomic generation, existing-visit and event-ID checks. [The durable store](infrastructure/PrismaMeasurementStore.ts) serializes those checks with principal erasure, issues scoped hash-only guest credentials and immutable foreground visits, and fences restoration against an independently supplied collector epoch. Identity's account-deletion transaction erases account principals; cascading keys remove linked raw history, staged outbox facts and the associated current guest visit. Core recovery cannot reconstruct those maps.

The [HTTP controller](presentation/MeasurementController.ts) is installed through [MeasurementModule](measurement.module.ts) and tested with the real public JWT guard. Bootstrap issues identities only with enabled purpose evidence; guest erasure remains available when collection is off. Runtime composition admits isolated tests and, in staging only, an exact operator-issued synthetic bootstrap proof whose protected configuration stores its SHA-256 digest and expiry. Admission expires within twenty-four hours and uses constant-time comparison; headers are redacted and confer no ordinary application authority. Public requests without that proof and all production issuance remain closed. Existing synthetic delivery also stops at the configured expiry. Durable PostgreSQL scenarios are defined in [the store suite](infrastructure/PrismaMeasurementStore.e2e.spec.ts); local unit evidence does not establish their runtime results. Collection remains unavailable and defaults closed. Production restore must supply a fresh external epoch and erase old collector identities before serving, alongside core deletion replay; reusing a backed-up epoch does not provide a restore fence.

Read [the measurement specification](../../../../../docs/prd/ops/85-launch-analytics-plan.md) before changing semantics. Feature outbox composition, host persistence, distributed resource proof, retention and admitted population/basis/rights evidence remain required. Do not treat fixture authority as real collection approval.

Improvement uses fixed Monday UTC weekly release keys shared by current/previous-week roles. [Recomputation](../../../../worker/src/measurement/RecomputeImprovement.ts) serializes each release and keeps published count groups immutable; [disclosure](../../../../worker/src/measurement/ImprovementDisclosure.ts) suppresses small per-metric cohorts/complements before persistence. Maturity-bound rates may publish once. Today exposes freshness only. [The UI policy](../../../../../docs/prd/ui/analytics-improvement.md#conservative-disclosure-resolution-2026-10-18) records the privacy limitations and departure from the rolling prototype. This synthetic-only policy does not establish anonymity or authorize live collection.
