# Diagnostics

Diagnostics owns one-center inspection intake, pinned templates, physical and publication authorization, staff assignments, observations, evidence, review and immutable report releases. Inspection-interest demand capture remains in [Reports](../reports/CONTEXT.md); provider Vehicle History belongs to service operations.

Intake and public release remain synthetic-only behind explicit runtime gates. A full-v3 campaign roster principal may instead reach template publication, buyer-private intake and their reads through `CampaignDiagnosticAdmission`. It derives the reservation from the stored roster email and serving candidate, takes the sorted diagnostics table locks before the namespace fence and requires the namespace authority to prove the live journaled User, its Session and each requested center, template, order or reception peer. Ordinary business authority, qualification and order checks still apply; it does not widen the runtime gate or use `operationalApproval`. A template or stored report does not authorize a real center, payment or public service. Private commissioners and currently assigned staff use separate authority from anonymous readers. Public access also requires the current eligible Listing and validated vehicle association. Identity edits invalidate that association permanently until an authorized reobservation; reverting Listing fields alone cannot restore it.

First drafts pin retained raw visit identity separately from their report state and release snapshot; same-visit corrections inherit that pin. Only currently qualified technicians/reviewers assigned independently to both visits can read the private comparison. Missing legacy pins refuse comparison, and commissioner erasure clears pins before intake erasure. Private manual/manual comparative and unchanged normalized-VIN automatic continuity proofs require a qualified reviewer independently assigned to both same-commissioner visits, distinct from the current linking technician. Issuance records one restricted proof and audit without creating a report; qualified technicians and reviewers assigned to both visits may read it. Declared evidence/provenance rights bound proof retention; erasure and worker expiry remove its restricted record. Source mutations permanently invalidate an unused proof. B's current linking technician consumes an unused proof once through proof-bearing reinspection input: under the issuance lock order the transaction rechecks the issuer's Session, qualification and both assignments, its own B authority and every bound version, hash, evidence generation, right and staffing digest, then marks the proof consumed, creates B's own empty linked draft and audits. The database admits a private reinspection only with that consumed proof; consumed proofs are never invalidated, and exact retries use the report's persisted proof/order-version binding. Automatic issuance additionally checks both observed VINs, independently retained consistent VIN stamps and unchanged raw identity history, with exactly one retained structured root per visit. Additional roots refuse; eligibility across multiple roots remains open. It retains the same distinct reviewer authority; broader automatic issuer eligibility remains unresolved. Mixed, corrected and public-transfer proofs stay unadmitted; hosted verification of automatic issuance/consumption is pending ([source evidence](../../../../../docs/evidence/issue-897/diagnostic-private-manual-consumption-source-20261021.md)). Structured identity evidence is order-owned and restricted: the assigned technician stages classified, rights-limited provenance before any bytes, uploads sanitized immutable images, then appends strict identifier records bound to the current raw record; a correction supersedes exactly one current record. First drafts also pin the current structured leaf, and comparison returns each side's raw observation, evidence chain and evidence generation, rechecking current authority on both orders before any provenance download. Expired rights, erasure and cleanup fence reads and retries. Collection stays synthetic-only; no hold powers exist. Released observations and their snapshot hash are immutable. Corrections create linked revisions without changing original dates or mileage. A reinspection is a new order's first report linked to a released or withdrawn report on another order; it starts with its own observation and template and reuses no findings or evidence. Without a proof, admission is temporarily limited to public orders with the same Listing, commissioner and observed VIN; corrected or changed identity and commissioner transfer remain refused pending the rest of the pair-bound proof implementation required by [ADR-0108](../../../../../docs/adr/0108-pair-bound-diagnostic-reinspection-continuity-proof.md). Continuity is checked only at insert, so later predecessor changes cannot block the surviving visit. A cross-order successor id is shown only to that order's commissioner or while it is publicly available. Evidence and per-locale PDF artifacts use dedicated private storage, exact hashes and generation epochs. Download authorization runs again after storage I/O. Account erasure fences access and cleanup before unlinking mutable intake; it preserves immutable observations under their governing retention rules.
