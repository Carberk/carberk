# Diagnostics

Diagnostics owns one-center inspection intake, pinned templates, physical and publication authorization, staff assignments, observations, evidence, review and immutable report releases. Inspection-interest demand capture remains in [Reports](../reports/CONTEXT.md); provider Vehicle History belongs to service operations.

Intake and public release remain synthetic-only behind explicit runtime gates. A full-v3 campaign roster principal may instead reach template publication, buyer-private intake and their reads through `CampaignDiagnosticAdmission`. It derives the reservation from the stored roster email and serving candidate, takes the sorted diagnostics table locks before the namespace fence and requires the namespace authority to prove the live journaled User, its Session and each requested center, template, order or reception peer. Ordinary business authority, qualification and order checks still apply; it does not widen the runtime gate or use `operationalApproval`. A template or stored report does not authorize a real center, payment or public service. Private commissioners and currently assigned staff use separate authority from anonymous readers. Public access also requires the current eligible Listing and validated vehicle association. Identity edits invalidate that association permanently until an authorized reobservation; reverting Listing fields alone cannot restore it.

First drafts pin retained raw visit identity separately from their report state and release snapshot; same-visit corrections inherit that pin. Only currently qualified technicians/reviewers assigned independently to both visits can read the private comparison. Missing legacy pins refuse comparison, and commissioner erasure clears pins before intake erasure. Structured identity evidence is order-owned and restricted: the assigned technician stages classified, rights-limited provenance before any bytes, uploads sanitized immutable images, then appends strict identifier records bound to the current raw record; a correction supersedes exactly one current record. First drafts also pin the current structured leaf, and comparison returns each side's raw observation, evidence chain and evidence generation, rechecking current authority on both orders before any provenance download. Expired rights, erasure and cleanup fence reads and retries. Collection stays synthetic-only; no hold powers exist. Released observations and their snapshot hash are immutable. Corrections create linked revisions without changing original dates or mileage. A reinspection is a new order's first report linked to a released or withdrawn report on another order; it starts with its own observation and template and reuses no findings or evidence. Its admission is temporarily limited to public orders with the same Listing, commissioner and observed VIN; manual or changed identity and commissioner transfer remain refused pending the pair-bound proof implementation required by [ADR-0108](../../../../../docs/adr/0108-pair-bound-diagnostic-reinspection-continuity-proof.md). Continuity is checked only at insert, so later predecessor changes cannot block the surviving visit. A cross-order successor id is shown only to that order's commissioner or while it is publicly available. Evidence and per-locale PDF artifacts use dedicated private storage, exact hashes and generation epochs. Download authorization runs again after storage I/O. Account erasure fences access and cleanup before unlinking mutable intake; it preserves immutable observations under their governing retention rules.
