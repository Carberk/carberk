# Vehicle History

The feature owns the local synthetic public offer and original fictional educational sample. Home and Listing detail use `HistoryEntry`; `app/vehicle-history/index.tsx` only passes optional Listing context. Availability defaults off and requires explicit development enablement with a loopback API. Messages opens the private request reader. `PrivateReader` lists cursor-paginated enquiries and opens their private transcript; `session` and `src/api/vehicle-history/requests` resolve storage and fence each read/result to a viewer and stable Session ID, including refresh retries. Context never grants seller access. `useHistoryContact` owns one attempt per explicit contact/New request, genuine auth cancellation/once replay, retry-key retention and current caller/session/create-result fences. New enquiries enter the real reader and invalidate only that session’s history; reopening is GET only. No provider, payment or marketplace Conversation is created.

`PublicOffer` owns sample presentation and recoverable file feedback. `saveFictionalSample` preserves the English document, verifies its local write, then opens the native export destination (iOS share sheet or Android document storage). Dismissal never claims an exported copy. Native storage/export is the test boundary; rendered component tests use the real feature and existing mobile harness.

`RequestConversation` reads ascending HTTP pages and owns the exact-text reply composer. `useHistoryReply` and `retainedDrafts` retain account/request drafts and each original uncertain send ID on the device across navigation and session replacement. Ordered writes precede transport; acknowledgement clears only its draft revision. Hydration and send results remain fenced to the mounted session/assignment. Send responses remain separate from fetched-page evidence; only contiguous HTTP pages permit receipts. Its mounted lifecycle owns contiguous page evidence and explicit received/read acknowledgements; only focused foreground viewable rows can become read. The current assigned operator and assignment epoch select other-party delivery facts. Query caches never establish receipt evidence for a new reader/session/assignment. Focus, reconnect and the active reader reconcile through HTTP using the root connectivity owners.

`PrivateReader` shows the current named operator and marks a later assignment
version as a handover in the customer's enquiry header. Pull refresh reads the
same requester-owned request; handover does not remove customer access.

`SourceListing` composes the existing public Listing route after the current private request supplies matching source context. Its read-only presentation omits seller/contact/owner mutations and returns through the original native stack, with the exact request as the cold-link fallback. It never widens Listing/media read authority or rewrites request facts.

`StopReminders` reads the server preference and retains an uncertain Stop version on the device, scoped to the customer/request/assignment. Stop is explicit and permanent; stale-version refusals reconcile before another explicit choice. Current session, request metadata and foreground fences discard late work. The conversation and its ordinary receipts remain available.
