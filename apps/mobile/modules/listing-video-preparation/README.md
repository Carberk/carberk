# Listing video preparation proof

Local Expo module, autolinked from `apps/mobile/modules`. `index.ts` supplies the `VideoPreparationPort` used through `VideoPreparation`, rather than letting an uploader consume the source URI. AVFoundation and Media3 Transformer 1.8.0 implement selected local-interval export, output validation, cancellation and deletion. This proof adds no seller UI or rollout activation.

Call `prepare` with a unique path-safe job ID, local source URI, millisecond interval and byte cap. Completion returns only a finished `prepared.mp4`, H264, AAC when audio exists, SDR BT709, at most 30 fps and a contained 720p envelope. Validation failure rejects and removes the owned partial directory. A completed ID is immutable; use another ID to replace it. `cancel` fences active output; `discard` explicitly deletes that ID's owned output. Both native engines persist a JSON completion journal after the file rename. Consumers must require the journal before recovering a file after process death. A recovery/list API and partial-directory sweep are future orchestration work, not supplied here.

The iOS proof app in `proof/NativeVideoProof.swift` compiles the same engine directly against the iOS Simulator SDK, consumes four public/synthetic fixtures and writes a JSON receipt to its Documents directory. It is a fixture-only application with a separate bundle ID, not a production route. The module podspec excludes the proof directory. Runtime receipt and remaining gates are in `docs/evidence/issue-888/verification.md`.

The source must remain reopenable during preparation. iOS supports sandbox file URLs, Android file/content URIs; neither promises to retain a third-party picker provider grant. Native preparation owns completed output, not the original source. Hardware/HDR compatibility and 10-minute/2-GiB/15-MiB resource limits remain provisional. Final founder recordings and consolidated native acceptance must establish activation readiness.
