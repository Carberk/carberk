# Native diagnostic decoder

This Android API 31+ source checkpoint decodes the documented `ApplicationExitInfo` tombstone protobuf in memory. It keeps only the numeric architecture/signal/code and crashing TID, the crashing thread's relative PCs, and output-only module aliases/build IDs matched to an actual protected release manifest. Manifest paths and ownership flags remain internal to the decoder and never enter the result. Unknown fields, absolute addresses, registers, paths, logs, memory, file descriptors, text and unrelated threads never enter the result.

The parser enforces the official `uint32` bounds for the root TID and thread-map keys. When the optional official `Thread.id` (`int32`) is present, it must be positive and equal to the map key; otherwise the record is refused as ambiguous. The source manifest constructor rejects duplicate paths and aliases before decoding, and unsigned length varints are bounded before any allocation.

The decoder is pure. `AndroidExitInfoPlatform.kt` now supplies the actual API-31+ `ActivityManager.getHistoricalProcessExitReasons` and `ApplicationExitInfo.getTraceInputStream` boundary. `ApplicationExitInfoHost.kt` admits at most eight records from one query with a ninth-record saturation sentinel, matches the current package UID, real UID and process name, and accepts exactly one own native crash. It preserves the OS death timestamp, enforces age <=300000 ms and future tolerance <=5000 ms before and after decoding, and closes the actual trace on success, refusal and exceptions. Missing, overwritten, stale, future and ambiguous records refuse without fallback. A non-progressing bulk stream read also refuses.

There is no production authority composition. The Android factories remain internal and closed, with no installed protected manifest or actor issuer. The internal testable host requires an immutable protected synthetic build manifest, a current generation/epoch admission and trusted exact-build/actor death-time interval. These input types are declarations, not verification. They must never be populated from JS, environment flags, current-build equality, founder permission or artifact helper metadata. A future protected native issuer must establish their provenance. There is no public bridge, registration, startup hook, network, SDK or signal handler. The dormant minimized cache source below is not composed into the app.

The OS read/minimize operation and local cache source below remain dormant. Protected lifecycle composition, atomic downstream transfer fencing, exact-build provenance and artifact association, symbolication, offline/restart delivery, collector behavior and native runtime evidence remain required integration work. Source preparation does not satisfy native acceptance.

The package intentionally has no JavaScript `main` entrypoint while the Expo module remains unregistered and inert.

Bounds are finite implementation limits: 2 MiB total wire bytes, nesting depth 16, 50 frames and 16 modules. Skipped unknown fields count toward the same byte cap. These limits do not change retention policy. Kotlin tests are authored beside the decoder but were not executed because native compilation is excluded for this source checkpoint.

## Minimized cache source

`NativeCacheCoordinator` now owns a single bounded minimized-event slot. It drives the real host and codec, serializes authority revision changes, cache commit/readout and destructive erase on one gate, and invalidates old in-flight OS work with a single-use revision ticket. OS streams remain outside the gate so logout, deletion, reset, restore and authority loss can invalidate and erase while a read is blocked. Cache readout revalidates the original event time with the same inclusive five-minute age and five-second future tolerance; it never changes the timestamp. Corrupt, oversized, unknown-format, foreign binding/build or stale records erase and refuse without another OS read. Failed erase permanently closes that owner and remains a reported failure, not successful deletion.

`NativeCacheCodec` stores only the strict minimized event plus opaque epoch and numeric generation. These two fields prevent rebinding old bytes after restart without storing an actor/User/Session/contact ID, full admission, credential, token or arbitrary metadata. Epoch provenance and durable lifecycle advancement must come from a future protected native integration. The binary format has bounded ASCII fields, bounded counts checked before list allocation, no extension map and no raw trace/manifest paths. The maximum permitted layout is smaller than the 16384-byte file cap.

`OneSlotNativeCacheStorage` performs fixed-buffer bounded reads and closes actual streams. `AndroidNativeCacheFiles` uses app-private `Context.noBackupFilesDir`, syncs/closes a pending file before atomic rename, syncs the containing directory, and deletes both the committed and pending paths. Orphan pending files are never restored or promoted. The coordinator must be the sole owner of this slot within one process. This source does not implement cross-process locking, arbitrary backup-tool protection, secure physical overwrite or a bound on blocking filesystem/OS latency.

Production remains unavailable. `dormantAndroidNativeCache` has no protected build, no issuer and no ability to accept source-test authority. It is unregistered and has no startup/bridge/network caller. `forSourceTests` and `replaceSourceTestAuthority` are internal fixture declarations only, not historical actor/build proof or a production authority API. Actual protected lifecycle wiring and durable epoch advancement are missing. In particular, deletion failure across process death cannot be certified safe without that protected durable fence. Normal Android backup excludes the chosen directory by API contract; actual artifact/backup/restore behavior is unverified. Cache-to-network delivery, server/collector erasure, collector translation, symbolication and native acceptance remain OPEN. All added Kotlin cases are authored and UNEXECUTED.
